# tools/perf — the World page audit (WLD-222)

`world-page-audit.mjs` is a **manual** CLI. It is not a test, not a CI step and not a schedule; nothing runs it but a person (or the lead's seat) in a quiet window.

```
node tools/perf/world-page-audit.mjs                  # one audit of real, signed-out https://postmark.town: ONE JSON line
node tools/perf/world-page-audit.mjs --backfill-bytes # repo-served bytes at each settlement/S* tag, from git only
```

- Pinned Playwright 1.62.0 (`package.json`), the bundled headless Chromium, a fresh signed-out context per sample, 1366×768, CPU slowed 4×, median of 3 samples.
- Measures cold-load bytes, time to map shown, time to interactive (C: a 2 s stutter-free window), pan-frame p95 and longest task at the Town Centre and at the Starforge Spire, plus idle CPU, heap after GC, drawn-mark count, and the served town's marks/parcels/settlement/shas. Every key's definition is in the file header.
- **C may be censored.** C is watched for 180 s of the page's clock after the map shows (a quiet window must end inside that, so the 2 s lookahead is inside the bound). A page that never goes 2 s without a long task is recorded as `>N s (never quiet: K long tasks, L ms total in the window)` with its bound and reason. A censored sample is still a sample: the cold-load bytes (cut off at the end of the observation window, named per sample as `bytes_basis: observation_end`), both pans, idle and heap still run. The 180 s is a *budget*, not an observation: a sample that goes quiet early stops watching at the end of its own 2 s window, and the row records the window actually observed (`observed_to_ms`) beside the budget. The row's C across samples is by **interval**, because each censoring bound is relative to that sample's own map-shown time: `[10 s, 184 s, >182 s]` has a median in (182 s, 184 s], and the row keeps that interval (`median_lower_ms`/`_lower_strict`/`_upper_ms`, `null` = unbounded) rather than invent a number. It is exact only when the intervals meet, and never a median of the finite subset.
- **Rows compare on the rendered frame**: the Site release's `code_sha` and the World snapshot (`world_sha`, `world_settlement`, `world_digest`). The release tags (`code_ref`, `world_ref`) are labels the Site stamps as `ref || null`: provenance in `row.tags`, may be null or renamed, never required or compared. The town's freshness (`town_sha`, `town_data_sha`, `crossing`, `town_index_as_of`) moves on its own clock and rides as per-sample provenance (`version_before/after`, `freshness_moved`, row `freshness_varied`); it never invalidates a sample. A frame change during or between samples does.
- **The drag, and a slow pan (Wright, 2026-11-22 21:09Z).** The ordinary movement test is >= 5 camera writes and >= 60 px of travel; both numbers stand. A completed real drag that travelled >= 60 px but yielded fewer than 5 writes is a **slow-pan finding, not invalid**, when its own pan p95 is >= 100 ms or its longest task is > 200 ms (the existing bars). The row lists it under `pan_stalled` with that phase's raw writes, travel, frame p95, longest task, frame count and long-task count; it is derived from the phase's own fields, never a flag the caller sets. Fewer than 5 writes with travel < 60 px, or below both bars, stays an inert drag (invalid), and every other phase/frame check stands.- **A re-read is not a measurement.** A row appended by re-applying the rules to an unchanged raw run carries `reread: {source, source_sha256, rules, note}`; its `at`, frame, CPU, samples and values are the original run's, and the original raw run (its file and hash) stays as history.
- Exit 0 = a valid row. Exit 2 = an **invalid** row (a failed phase or selector, a wrong place, an inert drag, a failed cold load, a changed frame…): the row is printed with `valid: false` and its reasons, and is never a baseline. A run against any other origin, or with other sample/CPU/bound settings, says `official: false`.
- Budget **15–30 minutes** for the official three samples at 4× CPU (a page that never goes quiet spends the whole 180 s bound per sample, then the idle, pan and heap phases; each wait between inputs is capped at 20 s). One Chromium (about 1–2 GB), one busy core, a few MB of public downloads per sample (the page pulled ~16 MB locally, mostly images). Run it with no crossing (00:00/12:00Z) or settlement (06:00/18:00Z) within 20 minutes and no other heavy run, through `run-heavy`.
- Results go to `PERF/world-page.jsonl`, one audit row per run, appended by the lead's seat only. The audit writes nothing and files nothing.
- Population and data identity come from the viewer's `/api/world/state` snapshot; `/build.json` names compiled code. The legacy `/WORLD/world-state.json` export is not substituted for that API population. Git-byte backfill lines (`kind: bytes-backfill`) describe selected repository engine/export artifacts, not a historical API payload or cold load; select `kind: world-page-audit` for browser-run trends.
- **Where each place is judged.** The Town Centre is "located" and "still in view" when its shape is under the middle of the map or the page's coordinate pill puts the camera within 500 m of the centre; the pill is read by the distances it prints (it says `at TC` only at exactly 0, 0 and `… of TC` everywhere else, so the words alone prove nothing). The Spire is judged by its shape only. **What the page read is judged over the whole sample**, not just the cold load: on the official origin a failed `/api/world/state` or `/api/world/skeleton`, any read of the legacy `/WORLD/world-state.json`/`skeleton.json` (the viewer's fallback, a different population), or no successful API read at all makes the sample invalid.
- **Committed rows may carry a few keys the code does not emit**: `context_reconciliation` and `env.measurement_code_sha` on the first audit row, and `file_set` on the git-byte backfill lines (the file list `DEFAULT_SERVED`). They were added by hand with disclosure; a row the tool writes itself will not have them.
- `tools/world-page-audit.test.mjs` is the offline check of the validity, censoring and comparator rules (pure functions; no browser, no network).
